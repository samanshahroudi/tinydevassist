# TinyDevAssist dataset registry

The first dataset candidate is [`samples/developer_support_v1.jsonl`](samples/developer_support_v1.jsonl): **36 original illustrative question/answer pairs** written for this project (six each in `git`, `python`, `http`, `api`, `debugging`, `ops`). The records were drafted with language-model assistance, are **not** real support transcripts, and have not yet undergone an independent technical review. This is a reproducible **seed dataset**, not evidence of production quality or a sufficient sample for strong generalization.

Read the [dataset card](DATASET_CARD.md) before using or redistributing it. The dataset is published under the repository's Apache-2.0 license, separately from the upstream base model. Do not mix in third-party documentation, code, private tickets, or personal data without provenance and licensing review.

## Raw record format

One UTF-8 JSON object per line:

```json
{"id":"git-001","category":"git","instruction":"...","response":"...","source":"project-authored-v1"}
```

Required fields are `id`, `category`, `instruction`, `response`, and `source`. IDs must be stable and unique. Prompts and responses must be nonempty English strings. The file is tracked so reviewers can audit exact source examples; derived train/validation/test files belong in ignored `data/processed/` and are generated by `prepare_data.py`.

## Deterministic preparation (Milestone 4)

```bash
python -m pip install -e .
python prepare_data.py --input data/samples/developer_support_v1.jsonl \
  --output-dir data/processed --seed 42
```

The preparation script validates all five string fields, unique IDs, and nonempty values;
normalizes Unicode NFC and whitespace; drops duplicate questions only when answers match;
rejects conflicting answers and near-duplicate questions (SequenceMatcher ratio >= 0.92)
for human review. It shuffles **within each category** using a seed derived from the supplied
seed and category name, then reserves approximately 15% per category for validation and
15% for test (at least one each). A category must contain at least three distinct questions.

For v1's six rows per category, the result is **24 train / 6 validation / 6 test**.
The generated JSONL contains the original normalized fields and a `messages` array with
`system`, `user`, and `assistant` role/content objects. The training code must apply the
model tokenizer's chat template, not hard-code special tokens.

`data/processed/manifest.json` records input SHA-256, output hashes, split IDs and category
counts, seed, normalization policy, and duplicate IDs removed. The script checks that IDs
and canonical questions cannot occur in multiple splits. It writes files only after source
validation succeeds. All generated files are ignored by Git.

**Limitations:** Similarity checks are character-based heuristics, not semantic paraphrase
detection. The six held-out test questions come from the same small, drafted source and are
not an independent benchmark. Do not use them for hyperparameter selection, and add
independently reviewed evaluation questions before claiming meaningful model improvements.
